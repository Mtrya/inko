# Posttrain data plan

后训练（单阶段 RL，DiffusionNFT/ART）的 prompt 与 rubric 全部自产、一轮生成，
不分批。DrawBench、GenEval、PickScore、HPS 等公开 benchmark 只作 held-out
监控与测试：它们全是通用域、英文为主、照片导向，测不到绘画风格域这一主要
训练目标，且训练使用其 prompt 会污染仅存的干净泛化信号。域内 held-out 由
自产池内部切分承担，公开 benchmark 提供跨分布校验。

预训练四域（D1/D2/D3/D4）主要是来源标签：人物/世界知识是题材，由种子内容
涌现、不按域预设。绘画两域同时锚定风格轴——d1 出国画、d2 出西洋画（图像
种子，图源即参考图，见生产管线）；d3/d4 以 caption 种子承载，风格随 caption
自然涌现（以摄影写实为主，含数字媒介与裸 prompt）。

## 生产管线

图像和 caption 是两种并行的种子，不混合使用——图与 caption 不对齐时，"按图
写风格、按 caption 写内容"必然冲突。

```
图像种子（绘画类，50%）：
  图一采自 d1/d2 各半（应用 manifest 裁剪框的版本）
  → 图二采自 d1/d2/d3/d4 各 25%（d1/d2 行同样用裁剪版）
  → 部署同款 PE（deepseek-v4.1-flash，视觉）看双图写 prompt：风格对齐图一，
    内容对齐图二；原 caption 全程不出现。prompt 必须自足——禁止"图一/图二/
    这一幕/原图/参考图"等指向种子图的表述，禁止引用种子属性的否定句（下游
    模型看不到种子图）；语域为 caption 式直接描述，禁止"画一幅/请以…画/
    Paint/Create"等命令式开头
  → 图一即该行的参考图，随 manifest 记录
caption 种子（50%，d3/d4 caption，风格随 caption 自然涌现）：
  原始 caption → 文本模型写 prompt（中档由 PE 改写；短档直写不过 PE——
  短档全部由 caption 种子承担，占其 20%），图像不参与
共同：
  → rubric 生成（图像种子由模型参考 prompt+参考图生成；caption 种子只看 prompt）
  → 校验与去污
  → 分层切分（train / dev / confirmation）
```

种子取预训练数据而非 LLM 凭空写：题材落在模型训练支撑集内，RL 修复的
是模型的真实弱点。最终 prompt 对齐部署分布——部署时模型输入是用户 prompt
经 PE 改写后的形态，因此全部 prompt 撰写都由部署同款 PE 模型
（deepseek-v4.1-flash）完成：caption 种子跑真实 PE 改写；图像种子由
flash 直接看双图写就（其视觉能力已在 zenmux 上验证），形态一致性在构造上
成立，无需 few-shot 校准。图像种子的内容源图二提供充足信息量，不存在凑
长度注入偏好的问题。

已知分布差异：P2 的输入是原始 caption（质量高、偏长偏详细），部署时 PE 的
输入是真实用户输入（可能极短、口语化、语法松散）。本池 prompt 形态接近
"PE 处理过长 caption 后的样子"，不代表部署分布全貌；部署 PE prompt 需单独
设计，P2 不能直接搬用。

d1 图源必须用裁剪版，不用原始整图：装裱与题跋区域会干扰风格判断。rubric
针对最终形态 prompt 生成，因为打分针对模型实际输入。rubric 生成与裁判同
模型同权重（Qwen3.8-27B）：写判据的感知能力与打分的感知能力一致，且 27B
在 sii 自部署上零边际成本（小规模 pilot 允许走 zenmux 图方便）。

## 边际分布

| 轴 | 分布 |
|---|---|
| 风格 | 国画 25%（图像种子，图一采自 d1）/ 西洋画 25%（图一采自 d2）/ 其余 50% 为 caption 种子（d3/d4）：**风格随 caption 自然涌现、不设风格指令**（硬指派对黑白纪实这类自带风格的 caption 会自相矛盾），生成后审计分布；裸 prompt（无风格指定）由涌现覆盖，不设配额 |
| 题材 | 不预设数字：图像种子的题材由图二涌现（d1/d2/d3/d4 各 25%），caption 种子由 d3/d4 caption 涌现；生成后审计，大题材塌陷（如人物 <15%）则调整图二采样分布再生一轮 |
| 语言 | 中英 50/50，不按风格×题材单元格差异化——双语是发布能力，每个单元格都需要双语覆盖 |
| 长度 | 短档 ≤30 tokens 10%（全部由 caption 种子直写，占其 20%）/ 中档 31–512 tokens、峰值 256 附近 90%（caption 种子 PE 改写 + 全部图像种子）；Qwen3 tokenizer 计量，与预训练文本契约同一度量 |
| 画幅 | **不写入 prompt 文本**（预训练 prompt 从不写画幅）；manifest 按方形 30% / 横幅 40% / 竖幅 30% 分配，rollout 与评估生成时应用 |
| 文字入画 | 不设目标、设地板：题字/印章/招牌/海报等文字渲染是预训练已涌现的能力（非训练目标），保留其曝光度。**认定标准收紧：prompt 必须含引号包裹的待渲染原文**（如"题'瑤臺霧浄'四字"），只写"有题字痕迹、不可辨"的不算。pilot 池按旧口径约 23%，按新口径重新审计，<10% 时补采。此类 prompt 的内容对齐条目逐字引用原文、核对字形，缺陷条目含错字/伪字/乱码检查 |

绘画类不再设子风格标签体系：参考图（图一）本身就是风格锚点，prompt 的风格
描述由撰写模型（flash，视觉）对图一直接观察写就，标签对齐问题在构造上不存在。风格多样性由
d1/d2 图源池的多样性保证；生成后审计 prompt 风格词汇的分布即可。

## 规模与切分

生成总量约 25k 条（参照 DiffusionNFT 的 25,432 条 pickscore 训练 prompt；
25k 池在 48 prompt/轮下每千轮每条平均复见约 2 次，prompt 过拟合风险低）。
生成放 10–15% 余量覆盖淘汰。

按风格/题材/语言/长度分层后切分：rollout train 约 24k、dev 500、
confirmation 500。dev 与 confirmation 永不进入 rollout；dev 承载配方选择期
的重复比较，confirmation 只在最终配置选定后跑一次。算法选择阶段（E0 起）
的 512 池与 monitor 48 不变，本池服务真跑。

成本预算 25k 全量 ≤¥1000。按新模型分配估算远低于此：撰写（P1/P2，zenmux
deepseek-v4.1-flash，实测约 $0.0003–0.001/行）+ rubric（P3/P4，
Qwen3.8-27B，sii 自部署零边际成本）合计约 $30/25k。pilot A 的成本大头
（87%）来自当时 rubric 用 v4-pro 且思考链 4k tokens，该结构已随 rubric
迁移到 27B 消除。sii 端点已验证：模型 id `Qwen3.8-27B`（大小写敏感），
Bearer 鉴权，仅 `/chat/completions` 路由接受 key（`/models` 不鉴权也不可
用）；文本、视觉、思考均可用，思考内容经响应的 `reasoning` 字段返回。

## Rubric 契约

固定五个大类，与 reward channel 一一对应。美术评分体系的成熟划分（联考
"审题/造型/构图/色彩/技法"，谢赫六法"应物象形/经营位置/随类赋彩/骨法用笔"）
印证了按职责切分的方向，但也暴露了旧契约的重叠问题——内容对齐、形态结构、
美学构图之间互相侵犯。各大类的边界因此明确为：

| 大类 | 管什么 | 不管什么 |
|---|---|---|
| 内容对齐 | 审题：prompt 指定的对象、属性、数量、关系、动作、文字是否**存在且正确**（事实判断） | 不评好坏；位置/姿态被 prompt 明确指定的归这里 |
| 形态结构 | 造型：主体形态、人体/动物解剖、透视、结构的物理合理性 | 不查存在性（归内容对齐） |
| 美学构图 | 经营：构图组织、色彩关系、光影、节奏的审美质量 | 以内容对齐成立为前提，不重复检查存在性 |
| 风格媒介 | 技法：有参考图时逐条锚定参考图（"与参考图相比，皴法/设色/笔触的接近度"），不自己发明标准；无参考图时按该媒介的惯例 | 不评内容 |
| 缺陷 | 伪影、崩坏、重复、多余肢体、水印、错字伪字、突兀的色卡/色块阵列、规则孔洞或网格状纹理（洞洞板） | — |

每个大类内含多条细粒度判据，要求 MECE：叠加覆盖该大类的全部判分点，互不
重叠，不越界到其他大类。判据仍须引用 prompt 具体词、指向可视特征（弱 VLM
对抽象词的感知不可靠）。生成模型可为判据标注相对重要性。裁判不逐条判定，
而是参考判据（及其重要性）对**每个大类输出一个总体判定**（A/B/tie）加一句
权重依据——判据是覆盖检查单，判分单位是大类。

文字入画的 prompt 必须含引号包裹的待渲染原文；内容对齐条目逐字引用原文、
核对字形，缺陷条目查错字/伪字/乱码。

打分形态为全 pairwise：组内 G 张图随机配成 G/2 对，每对做**双向两次**调用
（共 G 次）。同一大类两序一致则取该判定；不一致（翻转或 tie 摆动）记 tie。
看板实测同模型近质对上双向一致率 57–68%（完全翻转 4–17%），单序判定会把
位置噪声直接灌进奖励，双序合并把噪声中性化为 tie。"不稳率"按大类监控，
是 rubric 措辞质量的持续信号。

## 验收与去污

机械校验为硬门槛，不过即弃：schema（id、文本、语言、风格桶、种子身份（图像
种子记图一/图二行号，caption 种子记 caption 身份）、参考图字段（绘画类）、
画幅、长度档、形态）；文本与声明语言一致（CJK 占比）；长度落在声明
档位；判据非空、互不重复、引用 prompt 具体词；文字入画行含引号原文。

去污对 DrawBench/GenEval/PickScore/HPS 全部 prompt 文本：规范化 n-gram 硬
命中即弃，多语 embedding 相似度抓改写级近似（覆盖中文侧对英文 bench 的
跨语言雷同）。命中即弃不改写；命中率异常高说明生成器在复现 bench，调生成
而非调阈值。池内 embedding 近邻去重并统计生成模板指纹多样性。

## 风格知觉风险与参考图

弱 VLM（8B 量级）的风格感知可能不足：pairwise 解决校准问题，解决不了知觉
地板——编码器不表征的特征，两张图在裁判眼中同样"有点像"。判据具体化是
第一道缓解（无条件执行）。第二道是参考图锚定：绘画类 prompt 的参考图就是
其风格来源图一（图像种子的构造，见生产管线），把风格判断转为与锚点的相似
度比较；风格媒介大类的判据直接写成"与参考图相比"的形式。参考图与内容
允许同题材（同题材时技法差异反而更可比；题材碰撞自检会系统性地杀死
国画×花鸟、圣像画×圣母这类最自然的组合，不设）；裁判指令约束
style_medium 只评技法接近度，内容判断归内容对齐大类、不受参考图影响。
pilot B 已决定参考图激活（风格条目判对率 0.86→0.91）。

pilot B 同时暴露一条裁判偏置：所有受测裁判在"真迹 vs 模型仿作"对上判对率
0.02–0.13——强烈偏好干净鲜艳的生成图而非褪色古画真迹，风格条目上亦然。
VLM 裁判不能当真迹鉴别器；奖励只在同 prompt 生成图对内比较（本设计即如此），
"干净鲜艳"偏置列为训练监控项。

## Pilot

两个 pilot 已完成，产出不进正式池。

**Pilot A（管线验证，640 条）通过。** schema 633/640=98.9%（弃 7：rubric 缺失 4、
语言违规 1、计数违规 2）；各边际实现分布对设计偏差 ≤1.1%；去污对四个公开
bench 双侧（n-gram、embedding）零命中，池内去重弃 1，kept 632；短档均值
18 tokens，中档 p10/p50/p90=236/278/346，峰值 256 附近成立。抽检入档 50 条、
细审 11 条，可判性/具体性/非恒平全过。已知瑕疵：条目措辞风格不统一（陈述式
与疑问式混存，均可用）；无风格 prompt 的风格条目默认假设写实。成本 $7.81
（1412 次调用）。

**Pilot B（裁判探针）产出两个决定。** 已知序图对 58 对：质量对 16（20 步 vs
4 步生成）、风格确定对 21（真迹 vs 异风格真迹）、风格模型对 21（真迹 vs
模型仿作），全部双向呈现，判对率按条目计（better=1/tie=0.5/worse=0）。

- 裁判选型：Qwen3.8-27B、思考开。质量对 0.98、风格确定对风格条目 0.86，
  过 ≥80% 门槛；位置一致性 0.87–0.89。8B 在风格确定对上 100% 恒平，淘汰。
- 参考图：激活。思考开时风格条目 0.86→0.91；对质量对无影响。

**看板复核（pilot A 池 200 条，双 seed 生成 + 27B 双向判定）暴露了旧管线与
旧 rubric 契约的缺陷，直接驱动了本次重设计**：参考图事后匹配在 43 张小池上
17% 落到 domain 档、出现跨子风格错配（拜占庭圣像配浮世绘）——改为图像种子
构造（参考图=风格来源图一）；文字入画口径失效（prompt 不写待渲染原文，
rubric 无法核对字形）——认定标准收紧为引号原文；同模型近质对上逐条判定的
双向一致率仅 57–68%——判定单位从条目升到大类、打分改双序合并。

**Pilot2（新管线 200 行看板复核）又暴露两类缺陷并定案。** (a) P1 初版输出大量
引用种子图（"以图一的画笔画图二的场景"，8 行）与命令式语域（63/98 行"请以…
画一幅"开头），模板未声明自足性与语域所致；模板补两条硬规则后全量重跑，六类
禁用模式审计 0 命中。(b) 裁判输出协议对照试验（同 99 行、同双序、同 27B 思考）：
JSON 对象协议 vs 逐行 `大类|判定|依据` 协议，行协议不稳率 4/5 大类更低
（内容对齐 21% vs 33%、风格媒介 38% vs 47%、美学 37% vs 41%、形态 28% vs 34%、
缺陷 35% 持平），解析零失败且更便宜——裁判输出定案为行协议。同模型近质对上
残余不稳主要是真实难判（人工抽检确认两图无明显优劣），tie 是一等结果，
不应被强行摊成 1/0。

## 与训练侧的边界

本方案的产出只有 prompt 与 rubric。pairwise 结果标量化、channel 权重、
scorer 服务协议属训练/基础设施侧，不在此定义。配方跨奖励栈的迁移（算法
选择在 HPSv3+VQAScore 栈下完成，真跑以 rubric 为主力）届时需 bounded 复验，
不假设继承。
